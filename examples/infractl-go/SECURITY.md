## Authentication

| Mechanism | Where Used | Notes |
|-----------|-----------|-------|
| OS Keychain (macOS Keychain, Linux Secret Service, Windows Credential Manager) | Cloud provider authentication | Credentials retrieved at runtime, never cached in memory longer than a single operation |
| AWS IAM credentials | AWS provider (`internal/providers/aws/`) | Supports profile selection, STS assume-role |
| GCP service account / ADC | GCP provider (`internal/providers/gcp/`) | Application Default Credentials preferred |
| Kubeconfig | K8s provider (`internal/providers/k8s/`) | Reads from `~/.kube/config` or `KUBECONFIG` env var |

## Secrets Management

- **Never** hard-code secrets in source.
- **Never** store credentials in plaintext — all cloud credentials use OS keychain integration.
- **Never** log credentials — the audit logger explicitly redacts any field tagged as `Secret`.
- Secrets live in: OS keychain (local), HashiCorp Vault (production, P1 feature)
- Rotation cadence: Follows each cloud provider's rotation policy; InfraCtl does not manage rotation directly.

### Credential Flow

1. User configures credentials via `infractl config set-credentials --provider <aws|gcp|k8s>`
2. Credentials are written to OS keychain (never to disk files)
3. At operation time, the provider layer retrieves credentials from keychain
4. Credentials are held in memory only for the duration of the API call
5. On process exit, no credentials remain on disk or in memory

## Data Classification

| Level | Examples | Handling Rule |
|-------|----------|---------------|
| **Secret** | Cloud credentials, API keys, service account keys | OS keychain only, never logged, never written to disk, redacted in all output |
| **Internal** | HCL configs, resource names, audit logs, resource state | Stored locally in `~/.infractl/`, no PII in logs, append-only audit log |
| **Public** | CLI help text, documentation | No restrictions |

## Audit Logging

- All operations are logged to `~/.infractl/audit.log`
- Log format: timestamped, append-only, structured JSON
- Logged fields: timestamp, command, user, provider, resource, operation, result
- **Excluded fields**: credentials, secrets, API keys (redacted as `[REDACTED]`)
- Audit log is Internal-classified — may contain resource names but never secrets

## Dependency Policy

- Run `golangci-lint run` before merge — includes security linting (gosec)
- Audit deps with `govulncheck ./...` before release
- No wildcard versions in `go.mod`
- Pin all cloud SDK dependencies to specific minor versions
- Review all new dependencies for known CVEs before adoption

## Incident Response

1. Rotate compromised credentials immediately via the relevant cloud provider console
2. Notify #security channel
3. Create incident exec-plan in `docs/exec-plans/active/`
4. Review audit log at `~/.infractl/audit.log` for scope of exposure
5. Post-mortem within 48 hours placed in `docs/design-docs/`

## CLI-Specific Security Controls

- **Dry-run by default**: All destructive operations (`apply`, `destroy`) require explicit `--confirm` or `--yes` flag to execute
- **Confirmation prompts**: `env destroy` requires interactive confirmation before proceeding
- **No shell injection**: All cloud API calls use SDK methods, never shell-out to cloud CLIs
- **Binary distribution**: Single static binary, signed releases, checksum verification
