## Application Bootability

InfraCtl is a CLI tool (not a long-running service). It MUST be buildable and runnable from a clean worktree in 2 commands:

```bash
go build -o infractl ./cmd/infractl
./infractl --help
```

If build fails, `harnesskit doctor` MUST surface the root cause.

### Self-Check

| Command | Expected Result | Purpose |
|---------|-----------------|---------|
| `infractl --version` | Prints version and exits with 0 | Binary is functional |
| `infractl env list` | Returns empty list or managed envs, exits with 0 | Config and state subsystem works |
| `infractl apply --config test.hcl --dry-run` | Validates HCL and prints plan, exits with 0 | Config parsing and dry-run work offline |

> **Agents:** After ANY infrastructure change, verify the CLI builds and `infractl --version` succeeds before marking a task complete.

## Failure Modes & Mitigations

| Failure | Impact | Mitigation |
|---------|--------|------------|
| Cloud API timeout | Operation fails | Configurable timeout with clear error message; retry with exponential backoff (max 3 attempts) |
| Cloud API rate limit | Operation delayed | Automatic backoff; surface rate-limit info to user |
| Invalid HCL config | Operation rejected | Validate config before any cloud calls; clear parse error with file/line |
| Partial apply failure | Environment in inconsistent state | Rollback support: revert completed steps on failure; state tracked per-operation |
| Credential expiry | Auth failure mid-operation | Detect auth errors early; prompt user to refresh credentials |
| Network unavailable | Cloud ops fail | Offline operations (config validation, dry-run) still work; clear error for cloud ops |
| Corrupted local state | Incorrect drift detection | State file checksums; `infractl env status` reconciles with cloud |

## Safety Defaults

- **Dry-run by default**: `infractl apply` runs in dry-run mode unless `--confirm` is passed
- **Destroy confirmation**: `infractl env destroy` requires interactive confirmation or `--yes` flag
- **Rollback on failure**: Failed applies automatically roll back completed steps
- **Audit trail**: Every operation is logged to `~/.infractl/audit.log` for post-incident review

## Build & Release Safety

- **Single static binary**: No runtime dependencies, no shared libraries
- **Cross-compilation**: CI builds for all 5 platform/arch targets
- **Signed releases**: Binaries are signed; checksums published alongside releases
- Run `harnesskit enforce` in CI — block merge on architecture violations

## CI/CD Integration

> **Agents:** If `enforce` or `doctor` fail in CI, fix the violations before proceeding. Never skip or disable these checks.
