## Authentication

| Mechanism | Where Used | Notes |
|-----------|-----------|-------|
| JWT (Bearer tokens) | `/api/*` (all authenticated endpoints) | Short-lived access tokens, issued on login/registration |
| API Key | Stripe webhook endpoints | Stripe signing secret for webhook verification |

## Payment Security (Stripe / PCI)

- **PCI DSS compliance** is achieved by delegating all card handling to Stripe
- **No card data is ever stored locally** — Stripe Checkout Sessions handle card collection
- Payment tokens from Stripe are classified as **Secret** and are never logged or persisted beyond the transaction reference
- Webhook payloads are verified using Stripe signing secrets before processing
- Refunds (full and partial) are processed through the Stripe API, never by direct database manipulation
- Multi-currency support (USD, EUR, GBP) is handled entirely by Stripe

### Payment Data Flow

```
Browser → Stripe Checkout Session → Stripe processes payment
Stripe → Webhook → ShopWave API → Verify signature → Update order status
```

ShopWave never sees or handles raw card numbers, CVVs, or full card details.

## GDPR Compliance

- **User data is exportable**: Users can request a full export of their personal data
- **User data is deletable**: Users can request account deletion (right to erasure)
- **Consent tracking**: User consent is recorded for data processing
- **Data minimization**: Only data necessary for order fulfillment and account management is collected
- **Encryption at rest**: All user PII and order data are encrypted at rest in PostgreSQL

## Secrets Management

- **Never** hard-code secrets in source.
- Secrets live in: `.env` (local development), environment variables (production)
- Critical secrets: Stripe API keys, JWT signing key, database credentials, S3 access keys
- Rotation cadence: 90 days for API keys, immediate rotation on any suspected compromise

## Data Classification

| Level | Examples | Handling Rule |
|-------|----------|---------------|
| **Secret** | Stripe payment tokens, API keys | Never stored locally, never logged, vault-only access |
| **Confidential** | User PII (name, email, address) | Encrypted at rest, GDPR subject, access-controlled |
| **Internal** | Order data, recommendation models, metrics | Encrypted at rest, no public exposure |
| **Public** | Product catalog, marketing content | Cached aggressively, no restrictions |

## Incident Response

1. Rotate compromised secrets immediately (especially Stripe keys)
2. Notify #security channel
3. If payment data is involved, follow Stripe's breach notification procedures
4. Create incident exec-plan in `docs/exec-plans/active/`
5. Post-mortem within 48 hours → `docs/design-docs/`

## Agent Rules

- **NEVER** log payment tokens, user passwords, or PII
- **NEVER** store raw card data — always use Stripe Checkout Sessions
- **NEVER** disable webhook signature verification
- **NEVER** expose Stripe secret keys in API responses or frontend code
- When in doubt about a security decision, STOP and ask a human
- Never auto-generate secrets, tokens, or auth logic without explicit approval
